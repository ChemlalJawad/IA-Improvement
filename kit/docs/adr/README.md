# Architecture Decision Records

Write an ADR when a decision is architectural (layering exception, new dependency, persistence or messaging choice,
cross-cutting pattern) or when the agent proposes to break a rule of AGENTS.md. One decision per file.

- File name: `NNNN-short-title.md` (copy `0000-template.md`). Status: proposed, accepted, superseded by NNNN, rejected.
- Keep them short: context, decision, consequences. Link the spec or work item.
- Accepted ADRs that change a convention must also update `docs/ai/project-context.md` (the agents read that, not every ADR).
